# BIZ-11 补充非 Git 工作事项

## Goal

允许用户在报告周期内补充会议、联调、上线验证、线上支持等没有 Git commit 的真实工作，并让这些事实进入报告、AI 润色和历史记录。

## Requirements

- 在工作台报告周期控件附近提供可编辑的“补充事项”，支持多行短事项并明确仅用于当前报告草稿。
- 日报、周报、月报和自定义报告都能接收补充事项；生成的本地报告在无 AI 时也必须包含这些内容。
- AI 润色输入必须包含补充事项，并把它们标为用户提供事实，禁止推导未提供的结果或指标。
- 报告历史重新打开后保留补充事项及其生成文本；重新生成可复用原补充事项。
- 补充事项不得混入 Git 提交数、项目数或证据链统计。

## Acceptance Criteria

- [ ] 用户可为当前周期添加、编辑、清空多条补充事项。
- [ ] 四种报告模式的最终草稿均包含补充事项，且提交/项目统计不被改变。
- [ ] AI 请求将补充事项作为明确的用户事实传递，失败回退仍保留本地草稿。
- [ ] 历史记录保存并恢复补充事项；旧历史记录兼容加载。
- [ ] TypeScript/Rust 契约、单元测试和 Playwright 关键路径覆盖通过。

## Evidence

- 当前 `{notes}` 由 `src-tauri/src/report.rs` 写入固定免责声明，不是用户输入。
- 当前生成 option 与 `ReportHistoryEntry` 均没有补充事项字段。

## Out of Scope

- 团队协作、云同步、附件上传和自动抓取日历/工单。
