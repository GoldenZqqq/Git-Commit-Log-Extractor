# 重构首页工作台与仓库侧栏

## Goal

重构 GitPulse 首屏，让开发者在时间压力下能快速完成“确认范围并生成一份工作报告”，同时保留洞察、健康、历史、批量和仓库管理能力。重点解决当前首页信息密度高、主动作不明确、右侧仓库栏职责混杂和视觉噪声过大的问题。

## Background

- 用户确认改造范围覆盖整个首页，包括顶部、报告画布、空状态、结果动作和右侧仓库栏。
- 视觉方向为“安静、克制的专业工作台”：减少装饰，降低层级噪声，保留桌面工具所需密度。
- 评审快照位于 `.impeccable/critique/2026-07-21T11-57-18Z__src-components-workbench-tsx.md`，当前得分 24/40，认知负荷检查失败 6/8。
- `src/components/ReportCanvas.tsx` 在首屏并列报告类型、周期、生成、批量、空白日补写、复制和范围条；`src/components/WorkbenchAssistRail.tsx` 将仓库、历史和交付以同级 tabs 常驻右轨；`src/styles/tokens.css` 使用装饰性网格背景。
- 用户确认右侧保留更窄、始终可见的“本次范围”侧栏；仓库管理、映射和重扫通过二级入口展开。

## Requirements

- R1：首屏必须有唯一明确的主动作，默认路径是确认周期和范围后生成当前报告。
- R2：顶部收敛为工具栏级信息，移除与范围摘要重复的状态和统计；运行中状态仍须清晰可见。
- R3：报告画布按“报告类型/周期 → 范围确认 → 生成 → 结果处理”组织；复制、AI 润色和导出只在有结果时出现。
- R4：空状态必须说明将生成的报告范围、本地处理边界和下一步，不再只显示“暂无日报内容”。
- R5：右侧常驻窄侧栏默认只承担本次仓库范围选择；搜索和勾选可见，筛选、批量、映射、添加目录和重扫渐进展开。
- R6：保留仓库、最近和交付能力，但最近/交付作为侧栏二级视图，不与范围选择和报告生成争夺同等视觉权重。
- R7：仓库行使用清晰的选择语义与独立编辑入口，编辑映射不再依赖整行点击或 hover title 才能理解。
- R8：移除装饰性网格、大范围阴影、重复卡片边框和非必要英文 eyebrow；强调色只用于主动作、选中状态和真实风险。
- R9：保留焦点可见、键盘操作、浮层关闭、扫描取消、进度感知、暗色主题和窄窗口能力；补齐 tabs 方向键语义和关键 live-region。
- R10：不改变报告生成、仓库扫描、历史、导出和 AI 调用的数据流或业务行为，仅调整信息架构、呈现和交互编排。

## Acceptance Criteria

- [ ] AC1：默认桌面宽度下，用户能在 5 秒内识别唯一主动作，并可从空状态直接生成当前报告。
- [ ] AC2：首屏常驻主要决策点不超过 4 组；空报告时不显示复制、润色、导出等结果动作。
- [ ] AC3：顶部、报告画布、范围摘要和右侧侧栏形成清晰一级/二级层级，无重复状态抢占报告区域。
- [ ] AC4：侧栏默认显示已选数量、搜索和仓库勾选；管理动作有明确二级入口，仓库映射编辑有独立按钮。
- [ ] AC5：空、加载、成功、错误、无仓库、筛选无结果和全部禁用状态均有可执行下一步。
- [ ] AC6：浅色/深色主题、320px 窄窗口、640x450、1280x480 和 200% 等效缩放无溢出或文本重叠。
- [ ] AC7：tabs 支持可见焦点与方向键；关键进度可被辅助技术感知；主要交互目标尺寸与对比度符合现有桌面质量门禁。
- [ ] AC8：现有 frontend smoke、相关 Playwright、全量 E2E、生产 build 和真实 Windows WebView smoke 通过，无业务回归。
- [ ] AC9：桌面与窄窗口截图评审符合“安静、克制、可信”的工作台方向，不再呈现所有控件同等抢眼的仪表盘感。

## Out Of Scope

- 不重写 Rust 命令、报告生成算法、仓库扫描逻辑或持久化 schema。
- 不新增业务功能，不引入新的 UI 框架、组件库或依赖。
- 不把首页改造成营销页、数据大屏或纯移动端应用。
- 不新增复杂装饰动画；动效仅用于 150-250ms 的状态反馈和层级切换，并尊重 reduced motion。
