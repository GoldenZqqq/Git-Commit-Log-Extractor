# BIZ-26 迁移报告历史本地存储

## Goal

把报告正文历史从 WebView `localStorage` 迁移到 Tauri 应用数据文件，消除浏览器配额导致的静默丢失，同时保证旧用户升级无感、文件损坏可恢复、持久化失败不影响当前报告使用。

## Background

- `src/model.ts` 当前通过 `gitpulse-report-history` 键同步读写完整报告正文，并在配额失败时静默减半历史记录。
- `src/App.tsx` 把内存中的 `reportHistory` 作为工作台、报告日历和洞察视图的共同数据源；本次继续保持这一运行时边界。
- 设置和仓库索引仍使用各自现有的 `localStorage` 键，本任务只迁移报告历史。
- 历史条数设置只允许 30、60、120、200，默认值及现有排序、更新、去重语义保持不变。

## Requirements

### R1. Rust 文件存储

- Rust 提供加载、保存和清空报告历史的 Tauri 命令。
- 数据写入 Tauri `app_data_dir` 下的版本化 JSON envelope，报告正文不再写入 `localStorage`。
- 保存时先写同目录临时文件，再轮换主文件与备份；失败时恢复最近可用主文件并返回可理解错误。

### R2. 升级迁移

- 首次启动时，前端读取旧 `gitpulse-report-history` 值并只接受通过现有字段校验的数组。
- Rust 存储不存在时，把合法旧历史按当前条数上限写入文件；成功后前端删除旧键。
- Rust 主存储已存在时，以文件为权威数据源；合法旧键视为已完成迁移并清理，避免崩溃窗口导致重复导入。
- 旧值解析或迁移失败时保留旧键，继续提供可用内存数据并显示中文警告。

### R3. 损坏恢复

- 主文件无法解析或版本不支持时，将其隔离为带时间戳的 `corrupt` 文件，再尝试读取备份。
- 备份有效时返回备份内容并恢复主文件；没有可用备份时返回空历史和警告，而不是阻断应用启动。
- 恢复、迁移和正常加载都执行字段校验、去重及条数裁剪。

### R4. 前端单一持久化边界

- `reportHistory` 内存状态继续作为工作台、日历和洞察视图的唯一运行时数据源。
- 新增、更新、裁剪和清空统一通过一个持久化边界调用 Rust，避免在各业务函数中分散 `invoke`。
- 文件保存失败时保留当前内存历史和当前预览，并通过现有消息系统提示“本次变更未写入磁盘”。
- 清空失败时保留原历史；成功后主文件和备份都不得恢复已清空记录。

### R5. 兼容与测试

- 不改变 `ReportHistoryEntry` 对前端消费者的字段结构。
- Playwright Tauri mock 以文件存储状态替代 `localStorage` 作为断言来源，同时保留旧历史迁移 fixture。
- Rust 单元测试覆盖版本化读写、裁剪、迁移幂等、损坏隔离、备份恢复和清空。
- Playwright 覆盖升级迁移、正常保存、失败降级和清空；现有历史相关流程不得回归。
