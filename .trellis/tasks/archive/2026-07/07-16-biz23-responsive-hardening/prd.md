# BIZ-23 响应式与高缩放硬化

## Goal

保证 GitPulse 在 320px 极窄窗口、200% 缩放等效视口和小高度桌面窗口下仍可完成生成、设置、预览、复制与导出主路径。

## Background

- 产品仍是 Tauri 桌面工作台，目标输入方式为鼠标与键盘；极窄布局用于窗口缩放和系统放大，不改造成独立移动端信息架构。
- 全局 `body` 固定 `min-width: 980px` 且隐藏溢出，320px 和高缩放视口必然产生不可达内容（`src/styles/tokens.css:47`）。
- 1040px 以下工作台虽然改为单列，但 `.app-root` 与 `.workbench` 仍锁定视口高度并隐藏溢出，纵向堆叠后的辅助栏可能被压缩或截断（`src/styles/layout.css:1`、`src/styles/layout.css:299`、`src/styles/layout.css:771`）。
- 720px 以下工具栏已有部分纵向重排，但头部动作、分裂按钮、空白日入口和固定宽度 popover 尚未形成完整极窄屏契约（`src/styles/preview.css:1793`）。
- 设置弹层有内容滚动，普通 `range-dialog` 则缺少统一最大高度和滚动边界，小高度窗口可能使关闭入口离开视口（`src/styles/dialogs.css:16`、`src/styles/dialogs.css:1415`）。

## Requirements

- R1：移除 980px 全局宽度硬限制，在 320px 视口内不产生文档级横向滚动。
- R2：正常桌面宽度继续使用固定高度双栏工作台；空间不足时切换为单列、文档纵向滚动，不隐藏报告、辅助栏或关键操作。
- R3：头部状态/设置、工作台视图、报告类型、周期、生成、批量、补写、AI、导出和复制入口在极窄宽度下重排，不依赖横向滚动发现。
- R4：设置、批量和补写等主要弹层限制在可视区域内；小高度时内容纵向滚动，关闭按钮始终留在可视范围。
- R5：popover/menu 宽度不得超过当前可用视口，按钮文字和路径允许换行或省略但不得推开容器。
- R6：增加 320×900、640×450（1280×900 的 200% 等效 CSS 视口）和 1280×480 自动化场景；保留截图工件与关键 bounding-box/overflow 断言。

## Acceptance Criteria

- [x] AC1：320px 宽工作台 `documentElement.scrollWidth <= clientWidth + 1`，主路径控件无重叠、截断或不可达。
- [x] AC2：320px 与小高度窗口中的设置及主要弹层可滚动，关闭按钮 bounding box 始终位于视口内。
- [x] AC3：640×450 等效高缩放视口下可以生成日报、复制报告并打开/关闭设置。
- [x] AC4：1280×480 小高度桌面窗口仍保留报告预览和主操作，弹层不会越出上下边界。
- [x] AC5：三个场景均输出 Playwright 截图，关键区域没有内部横向溢出，前端构建与全量 E2E 通过。

## Out of Scope

- 不新增移动端导航、抽屉或触摸专用交互。
- 不改变桌面宽屏下的双栏结构、报告信息层级或业务动作。
- 不支持小于 320 CSS 像素的窗口，也不在本任务引入真实系统级缩放驱动。
