# 增加隐私安全的支持诊断包

## Goal

让用户在不泄露仓库内容、凭据和本机路径的前提下，生成可检查、可离线保存的支持材料，并用安全摘要低摩擦地创建 GitHub Issue。

## Background

- 当前诊断页已通过 `run_diagnostics` 展示 Git、工作区、输出目录、AI、字体和网络检查，但没有可导出的支持快照。
- 工作区健康检查已有根目录与仓库状态模型；支持包只能聚合状态计数，不得复制原始路径、仓库名或分支名。
- 应用没有持久化日志基础设施。“近期应用日志”在本任务中定义为当前进程内、最多 50 条高层应用事件；关闭应用后清空，不写 localStorage 或应用数据目录。
- 支持包使用现有本地 ZIP writer，无需新增依赖。保存由用户选择本机路径，不依赖 GitHub、AI 或其他网络服务。
- 大型工作区性能基线任务已经归档；本任务沿用整数毫秒、结构化结果和有界输入的口径，但不把真实工作区数据送入性能或远端服务。

## Requirements

- R1：诊断页提供“准备支持包”入口；Rust 先生成脱敏预览，用户查看固定文件清单并显式确认后，才能选择位置导出 `.zip`。
- R2：支持包固定包含 `summary.md`、`diagnostics.json` 和 `recent-events.log`，记录 schema 版本、生成时间、GitPulse 版本、平台、架构、Git 版本、诊断计数与条目、工作区健康状态计数、检查耗时、失败步骤和有界应用事件。
- R3：支持包不得包含 API Key、OAuth token、代理密码、代理用户名、OAuth 邮箱、原始 commit 内容、报告草稿、报告历史、项目映射、仓库/分支名称或绝对私有路径。
- R4：应用事件只保留当前会话最近 50 条非加载状态消息；前端限制单条长度，Rust再次限制数量、单条长度和总大小。事件不持久化，只有用户点击准备支持包时才进入 Rust 脱敏流程。
- R5：Rust 对已知私有值以及 Windows/UNC/Unix 绝对路径、邮箱、Bearer/API key/token/password 形态做集中脱敏；写入前必须重新经过同一安全构建路径，不能直接把 WebView 文本打包。
- R6：预览展示三个条目的脱敏内容、明确排除项和安全 Issue 摘要。导出取消、写入失败、预览失败与浏览器打开失败均给出中文可操作提示。
- R7：复制摘要与“打开 GitHub Issue”只使用 Rust 返回的短安全摘要。Issue URL 不携带事件详情或本地文件，不自动上传/附加诊断包，用户可自行决定是否手动添加文件。
- R8：所有预览与导出操作保持 local-first；无网络时仍可预览、复制和保存支持包。不得增加遥测、后台上传、崩溃自动上报或常驻日志采集。

## Acceptance Criteria

- [x] AC1：Rust 测试注入 Windows/Unix 路径、仓库名、分支、作者、邮箱、API Key、Bearer token 和代理密码后，三个文件与 Issue 摘要均不包含原值。
- [x] AC2：Rust 测试覆盖 schema、固定 ZIP 条目、健康/诊断计数、事件数量/长度上限、输出扩展名、写入失败和完全离线生成。
- [x] AC3：用户能在诊断页打开支持包预览，逐项查看脱敏内容；未勾选确认时导出不可用，关闭后焦点回到触发按钮。
- [x] AC4：用户确认后可通过系统保存对话框导出 `.zip`；取消不报错，失败显示中文提示，成功显示保存结果。
- [x] AC5：复制内容和 GitHub Issue URL 只包含安全摘要；E2E 断言链接不含本机路径、日志详情或附件参数。
- [x] AC6：支持包弹层通过键盘焦点、Escape、axe 严重/致命问题和窄屏/小高度检查；现有 build、E2E、Rust 测试、真实 Tauri smoke 与 `git diff --check` 保持通过。

## Out Of Scope

- 不自动上传支持包，不新增服务器、账号、遥测、崩溃收集或后台网络请求。
- 不读取操作系统日志、Git 历史、commit message、报告正文、报告历史文件或安全凭据库内容。
- 不承诺恢复应用重启前的日志；持久化日志与崩溃恢复属于独立安全设计。
- 不在 Issue URL 中嵌入 ZIP、base64 日志或本地文件路径，也不调用 GitHub API 创建 Issue。
