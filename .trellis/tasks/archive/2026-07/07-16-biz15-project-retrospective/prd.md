# BIZ-15 增加项目回顾视图

## Goal

在现有数据洞察中提供项目维度回顾，让用户不重新扫描 Git 即可按项目查看近期报告、项目提交量、证据编号以及 AI 润色和导出状态，并能打开原报告继续工作。

## Background

- BIZ-26 已将报告历史迁移到版本化的本地文件存储，项目回顾应只消费内存中的 `ReportHistoryEntry[]`，不新增第二套持久化或 Git 扫描链路。
- 当前日报和自定义报告返回提交明细，周报和月报只返回总量；四种报告尚无统一的结构化项目归属字段。
- 报告正文受模板、作者分组、项目映射和脱敏影响，不能作为可靠的项目身份来源。
- 历史记录最多保留 30、60、120 或 200 条，项目回顾属于这组本地历史的派生视图，不承诺超出历史保留范围的长期分析。

## Requirements

### R1 结构化项目归属

- 新生成的日报、自定义报告、周报和月报必须在历史记录中保存可选的结构化项目列表。
- 每个项目项包含展示名称、该报告内的项目提交数和可追溯证据编号。
- 项目展示名称必须复用报告渲染中的精确分支映射、通配映射、末尾连接符清理和仓库/分支回退规则。
- 证据编号使用现有七字符短哈希规则；每个项目每份报告最多保留 20 个证据编号，但提交总数必须保持准确。
- 开启脱敏时，仅持久化脱敏后的项目名称和 `commit-N` 证据编号，不得把原仓库、分支或提交哈希写回历史。

### R2 兼容与归类

- `projects` 字段保持可选，现有历史文件和旧 localStorage 迁移数据无需重写即可加载。
- 缺少 `projects` 字段的旧历史和空白日补写草稿统一归入可预测的 `未归类历史` 项目。
- 明确包含空 `projects` 的零提交新报告不伪造项目归属，也不出现在 `未归类历史` 中。
- 不从 Markdown 标题、正文或文件名猜测项目。

### R3 项目回顾交互

- 在数据洞察的报告日历之后、节奏与趋势之前展示全宽项目回顾区域。
- 用户可选择项目，并按近 30 天、90 天、180 天或全部历史筛选；时间范围以报告日历锚点日期为准。
- 汇总展示筛选结果内的报告数、项目提交数、已导出报告数和去重证据数。
- 时间线按报告日期和生成时间倒序，逐条展示报告类型、周期、该项目提交数、AI 状态、导出状态和证据编号。
- 同一份多项目报告可出现在多个项目时间线中，各自使用项目级提交数和证据编号。
- 点击条目的打开按钮必须沿用现有 `onOpenHistory` 行为，不新增预览副本或弹层。

### R4 状态与可用性

- 提供无报告历史、仅有未归类历史、所选时间范围无结果三类明确空态。
- 项目和时间控件具有可访问名称；证据过长时可换行，不得撑破窄视口。
- 组件必须在浅色、深色主题以及桌面和窄视口下保持可读、无重叠。

## Acceptance Criteria

- [x] AC1：新生成的四种报告历史均保存结构化项目归属，映射名称、项目提交数和七字符证据编号正确。
- [x] AC2：同一报告包含多个映射项目时，可分别选择项目并看到同一原报告的项目级统计。
- [x] AC3：脱敏报告历史不包含原项目名、原分支名或原提交哈希，AI 润色接受后仍保留同一项目归属。
- [x] AC4：旧历史和空白日补写出现在 `未归类历史`，空项目新报告不被误归类，且不解析 Markdown。
- [x] AC5：30/90/180 天和全部筛选按报告锚点日期工作，汇总与时间线结果一致。
- [x] AC6：报告数、项目提交数、已导出数、去重证据数及 AI/导出状态显示正确。
- [x] AC7：点击项目时间线条目可打开原历史报告并切换到对应预览。
- [x] AC8：无历史、未归类历史和无时间范围结果均有自动化覆盖；浅色、深色、桌面和窄视口完成视觉检查。
- [x] AC9：Rust 测试、Clippy、前端构建、完整 Playwright 和 `git diff --check` 通过，或对非本任务既有问题给出可复现证据。

## Out of Scope

- 重新扫描 Git、读取已导出的 Markdown 文件或建立独立分析数据库。
- 从旧报告正文启发式恢复项目归属。
- 跨历史记录合并同名但语义不同的映射项目，或提供项目重命名/合并工具。
- 修改报告历史保留上限、搜索能力、云同步、加密或多窗口并发模型。
- 增加项目详情弹层、独立路由、图表导出或复盘数据编辑能力。

## Dependency

- 依赖已完成并归档的 BIZ-26 报告历史本地文件存储。
