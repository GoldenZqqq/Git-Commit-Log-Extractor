# 修复长任务进度通知闪烁

## Goal

让扫描仓库和生成报告等长任务始终复用同一个全局进度通知，在任务执行期间原位更新文案，并在成功、失败或取消后用同一通知实例收尾，避免多仓库进度事件触发反复闪烁。

## Background

- `src/App.tsx` 的 `showMessage` 为每次通知创建新的 `Date.now()` ID，`AppMessageHost` 又使用该 ID 作为 React key，因此高频进度事件会反复挂载通知并重播入场动画。
- 提交提取进度文本采用“提取中 · …”，当前 tone 推断仅识别“提取中：…”，导致进度被当作普通信息通知。
- 仓库扫描进度目前只更新工作台状态，不更新已弹出的全局 loading 通知，和报告生成的反馈方式不一致。
- 批量报告、空白日扫描、应用更新等流程已有各自的内联进度区域，不应额外引入重复的全局逐项通知。

## Requirements

- 长任务开始时显示一个不自动消失的 loading 通知。
- 同一长任务的进度更新必须复用当前 loading 通知实例，不重播入场动画。
- 仓库扫描与提交提取事件都应在该实例内原位更新可读进度。
- 成功、失败或取消消息应复用当前 loading 通知实例，并恢复合理的自动关闭时长。
- 普通离散通知仍应创建独立实例并保持现有关闭行为。
- 不改变 Rust 事件协议，也不重复替代已有的对话框或横幅内联进度。

## Acceptance Criteria

- [x] 连续提交提取进度事件只保留一个 `.app-message` DOM 节点，节点身份稳定且文本更新。
- [x] 仓库扫描期间全局通知持续可见并原位显示最新目录与仓库计数。
- [x] 长任务完成或失败后，同一通知节点切换为最终状态并按既有时长自动关闭。
- [x] AI 润色、导出等通过统一任务运行器启动的 loading 通知也不会在最终状态切换时重建。
- [x] 普通通知、关闭按钮、无障碍 live region 与现有内联进度保持可用。
- [x] `npm run build`、相关 Playwright 测试、全量 E2E 与 `git diff --check` 通过。

## Notes

- 本任务边界局限于前端通知状态与测试，采用 PRD-only 轻量流程。
