# 空白日补写日报

## Goal

在日报场景下，当用户当天（或所选目标日）没有足够可写的新提交时，提供「空白日补写」能力：基于用户选定的历史 **素材周期** 与勾选 **仓库** 的真实 Git 提交线索，用 AI 生成一份**克制、可编辑、可核对**的日报延续草稿，降低空白日写日报成本。

用户价值：不是鼓励造假，而是把「今天仓库静悄悄但还要交日报」变成可操作的草稿流程。

## Background

- GitPulse 已有「生成日报」与「AI 润色」。AI 润色明确禁止虚构提交之外的成果。
- 本功能是**独立模式**，与 AI 润色并列，不修改润色语义。
- 入口文案可带轻微幽默，但产品主名与系统提示词必须克制、可追溯。
- 已有 `batch-report-gen` 任务仍在进行中；本任务独立规划，不与批量生成混做。

## UX Flow（已定 MVP）

```
日报 Tab 工作台
  → 「生成日报」旁显示「空白日补写」按钮
  → 默认展开吸引气泡（可关闭；关闭后本机记住，不再自动展开）
  → 点击按钮打开弹窗
  → Step A：选择目标日 + 素材周期 + 条数
  → Step B：展示素材周期内涉及的仓库/分支 Tag（默认全选，可取消）
  → Step C：确认/修改默认 Prompt
  → 点击「生成草稿」
  → 结果写入可编辑文本区，可复制；确认后可应用到日报预览
```

### 入口位置

- 仅在 **日报预览模式**（`activePreview === "summary"` / 日报）显示按钮与气泡。
- 位置：预览区工具栏，紧挨「生成日报」与「批量」一组，位于其右侧。
- 周报 / 月报 / 自定义模式不显示本入口（MVP 不做）。

### 吸引气泡

- 相对「空白日补写」按钮上方或右上锚定。
- 默认展开；提供关闭「×」。
- 关闭后写入本机偏好（如 settings / local preference），下次不再自动展开；按钮仍可用。
- 不阻断主流程，可点按钮直接开弹窗。

### 弹窗结构

1. **顶部 disclaimer**（固定，不可关）
   > 本内容基于历史 Git 提交线索推断生成，不是当天真实提交记录。请核对后使用。

1b. **目标日有提交时的轻提示**（条件展示，非阻断）
   > 目标日已有提交记录，补写将基于历史线索生成延续草稿，不会替代真实提交摘要。也可先点「生成日报」。

2. **目标日**
   - 默认 = 当前日报日期选择器的日期（通常是今天）。
   - 用户可改目标日（补写某一天的日报）。

3. **素材周期**
   - 开始日 / 结束日。
   - 默认：目标日往前 **3 个自然日** 至目标日前一天（不含目标日本身）。
   - 若区间无提交，提示用户扩大区间或检查作者/仓库启用状态。

4. **生成条数**
   - 可选：3 / 5 / 8，默认 **5**。
   - 上限 8，避免注水感。

5. **仓库 Tag 区**
   - 用户选定素材周期后，扫描并列出该区间内**有提交**的仓库（及分支展示）。
   - 每个「仓库（分支）」一个可勾选 Tag，默认全选。
   - 无提交的仓库不出现在列表中。
   - 至少勾选 1 个才可生成。

6. **Prompt 输入框**
   - 多行文本，预填默认 Prompt（可编辑）。
   - 提供「恢复默认」小操作。

7. **底部操作**
   - 取消 / 生成草稿。
   - 生成中禁用重复提交；展示 loading。

8. **结果态（同一弹窗内切换或下方展开）**
   - **结果形态已定：N 条短要点列表**（不是长段落）。
   - 默认每行一条，可用 `- ` 前缀；条数与用户选择的 3/5/8 对齐。
   - 放入可编辑 textarea，允许删改/合并后再复制。
   - 操作：复制全部 / 应用到预览 / 重新生成 / 关闭。
   - 「应用到预览」：预览为空则直接写入要点列表；预览非空则二次确认「将用补写草稿替换当前预览内容？」后整段替换。
   - 应用前保留「补写草稿，请人工核对」语义；应用后可继续编辑、导出。

## Default Prompt（2026-07-16 收紧具体性）

系统侧约束（用户不可见，实现时写入 system prompt）：

- 只能依据提供的历史提交主题、模块与仓库线索写作。
- 每条必须引用历史线索中的具体功能、接口、数据流、页面、脚本、测试、异常路径或技术对象。
- 优先写功能延伸、潜在缺陷/回归修复、异常与边界处理、兼容性完善、测试补强或已有接口/数据流衔接。
- 不得只写「跟进 / 排查 / 推进 / 联调 / 整理」；如使用，必须同时写明具体对象、问题模式和拟采取动作。
- 禁止：已上线、已验收、具体业务结果、虚假百分比、从未出现过的模块、把历史提交日期改写成目标日真实提交。
- 语言简洁正式，适合直接复制到工作日报。
- 输出恰好 N 条短句/要点，不要长文复盘。

用户侧默认 Prompt（可见、可改）：

```text
请基于我提供的历史 Git 提交线索，为目标日写一份具体、可核对的日报延续草稿。
要求：
1. 每条必须从历史线索中指出一个具体锚点
2. 优先写功能延伸、缺陷或回归修复、异常/边界/兼容性处理、测试补强，或已有接口与数据流衔接
3. 不得只写「跟进 / 排查 / 推进 / 联调 / 整理」；如使用，必须写清具体对象、问题模式和拟采取动作
4. 潜在缺陷只能写拟采取的保护或修复动作，不得断言故障已经发生
5. 保留项目前缀、严格输出 N 条短要点，并避免同义改写和注水
6. 不要写已上线、已完成验收、百分比进度等无法核实的表述
```

## Constraints

- 必须配置 AI 才能生成；未配置时按钮可点但弹窗内主 CTA 禁用并引导去设置（与 AI 润色一致）。
- 不绕过作者范围、仓库启用等现有扫描约束；素材扫描复用现有 Git 提取能力。
- 不把补写结果伪装成「当天有提交」的本地生成日报；必须写入历史并标记来源为空白日补写 / 补写草稿。
- API Key 不进明文配置；沿用现有安全存储。
- MVP 不做：企业 IM 直发、自动定时、幽默文案开关 UI、周/月报补写、完全无 AI 的本地假生成。

## Requirements

1. **R1 入口**
   日报模式下，在生成日报按钮组旁提供「空白日补写」按钮；默认展示可关闭吸引气泡，关闭状态可持久化。

2. **R2 弹窗配置**
   支持目标日、素材起止日、生成条数（3/5/8）、仓库 Tag 多选、可编辑 Prompt（含恢复默认）。

3. **R3 素材扫描**
   根据素材周期 + 当前作者范围 + 启用仓库，列出有提交的仓库/分支供勾选；展示空态引导。

4. **R4 AI 生成**
   将勾选仓库的历史提交摘要 + 用户 Prompt + 条数 + 目标日，调用专用补写链路（独立于 AI 润色 system prompt），返回可编辑草稿。

5. **R5 结果应用与历史**
   支持复制与「应用到预览」（非空预览需二次确认后整段替换；空预览直接写入）；应用后可继续编辑、导出；保留「补写草稿」语义。
   生成成功后写入报告历史：标题 `空白日补写 · {目标日}`，标记来源为 `补写草稿`，与普通日报 / AI 润色记录可区分。

6. **R6 安全与克制**
   固定 disclaimer；生成约束禁止结论性虚构；失败时展示可读错误且不污染原预览内容。

7. **R7 有提交日亦可补写**
   目标日存在真实提交时仍允许进入补写并生成；弹窗展示非阻断轻提示，引导可选用「生成日报」。

## Acceptance Criteria

- [x] AC1：仅日报模式可见「空白日补写」入口；周/月/自定义不可见。
- [x] AC2：首次进入日报模式默认展开气泡；关闭后重启应用不再自动展开。
- [x] AC3：默认素材周期为目标日前 3 个自然日至前一日；默认条数 5；默认 Prompt 可恢复。
- [x] AC4：选择素材周期后，仅展示该区间有提交的仓库 Tag，默认全选，可取消；未勾选时不可生成。
- [x] AC5：未配置 AI 时不能成功生成，并引导配置。
- [x] AC6：已配置 AI 且素材充足时，可生成恰好约 N 条短要点的可编辑草稿；内容不出现「已上线/验收通过/精确百分比」等明显结论性虚构（以 prompt 约束 + 抽样验收）。
- [x] AC7：复制与应用到预览可用；应用不覆盖用户未确认的其他预览操作异常；原「生成日报」流程不受影响。
- [x] AC8：AI 润色的「不虚构」语义保持不变；补写使用独立 prompt/入口。
- [x] AC9：关键路径有基础错误处理（无提交、网络/模型失败、取消）。
- [x] AC10：生成成功后报告历史出现对应条目，标题含「空白日补写」与目标日，来源标记为补写草稿；筛选/展示不与「普通生成日报」混淆。
- [x] AC11：目标日已有提交时仍可打开补写并生成；展示非阻断轻提示；不自动禁用主 CTA。
- [x] AC12：应用到预览时，空预览直接写入；非空预览弹出二次确认后整段替换；取消确认则不改预览。
